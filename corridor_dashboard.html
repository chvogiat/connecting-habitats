What this page solves, and what it does not

The tree is heuristic. The page runs Algorithm 1 of the module (Kou–Markowsky–Berman). It never proves optimality. On the frozen instance the heuristic sits 10–14% above the exact optimum, so a corridor that looks like the optimum is not a certificate that it is one. Run steiner_exact.py for that.

The budget frontier searches subsets but not trees. Which p patches to serve is part of the problem, so the page evaluates every size-p subset containing the root and keeps the cheapest heuristic tree. What remains is the heuristic gap. Two cautions carry over from the module: the exact optimal designs at successive p are not nested, so a step on this frontier is the difference between two separately optimized networks; and corridor_budget.py solves the same quota problem exactly. Because the search ranks subsets by heuristic cost, it can still prefer the wrong patches: for the deer at p=7 it drops Embarras Headwaters where the exact model drops Salt Fork Wetland, and it is right to, given the trees it can see. Comparing the two lists is a good exercise.

“Road aversion” is an exponent, not the module's ρ. The slider raises every class multiplier to the power γ, so γ=0 flattens the classes to pure distance and γ=1 restores the species profile. The profile sweep in the module instead sets rc=ρrank(c)/7. Both change profile shape; they are not the same parameter. Multiplying a whole profile by a constant would change nothing at all.

Consensus is a selection frequency. The shading is how often a segment appears across perturbed re-solves under the stated σ, not a probability that the segment belongs in an ecologically correct corridor, and not a validation of anything. With “all species” on, each segment is scored by its minimum frequency across the three species, which is a definition local to this page.

The survivability model is not here. The comparison the module is built around needs the exact program: see corridor_redundant.py.
